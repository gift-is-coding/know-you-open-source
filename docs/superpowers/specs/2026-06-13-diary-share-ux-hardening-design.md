# 日记分享 UX 修正设计

## 背景

第一版日记分享已经能生成图片，但真实使用时出现了几个会阻断传播的细节：分享控件跟英文产品不一致、用户复制前看不到图片预览、长日记被固定画布截断、划选后右键分享没有弹窗反馈、脱敏痕迹不够明显。

## 目标

- 分享入口、弹窗、右键菜单、复制反馈统一使用英文。
- 点击顶部分享或右键分享后，都进入同一个独立 popover，而不是直接复制或在正文下方展开。
- popover 默认勾选 redaction，除非用户主动取消。
- popover 在 `Copy Image` 和 `Save Image` 上方展示当前分享图片预览。
- 分享图片正文区域按内容动态增高，长日记不截断。
- 脱敏后的敏感片段在文本和图片里以明显遮挡块显示。

## 非目标

- 不做云端 AI 脱敏。
- 不做社交平台一键发布、短链统计或增长归因。
- 不修改日记生成、My Wiki、source detail 或事件采集逻辑。

## 交互要求

- 顶部按钮文案为 `Share Redacted`。
- 弹窗 checkbox 文案为 `Redact sensitive details`，打开弹窗时默认勾选。
- 复制成功后显示 `Copied. You can paste it elsewhere.`，同时保留短暂 toast，避免用户不知道是否成功。
- 右键菜单提供 `Share Redacted` 和 `Share Original`，选择后打开 popover。弹窗内容使用当前划选文本；如果无法可靠取得选区，则回退当前段落。
- 保存图片仍然打开系统保存面板。

## 脱敏策略

分享脱敏仍然是本地展示层规则，覆盖 email、长数字、手机号/订单号、password/token/secret/API key/bearer 键值、private key block、URL query/fragment。脱敏结果使用明显遮挡块，例如 `████████`，而不是 `[email]` 这类弱提示。

## 验收标准

- 中文日记内容下，分享 UI 仍然全部是英文。
- 打开分享弹窗即可看到预览图。
- 超过一屏的长正文会生成更高的图片，不丢失后半段内容。
- 右键分享选中文字不会直接复制，而是先弹出分享 popover。
- 脱敏分享图中敏感信息不可见，并显示明显遮挡块。
