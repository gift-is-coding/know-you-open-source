# KnowYou Channel Playbook

Use this when drafting channel-native copy or deciding which channels belong in a feature launch.

## Default Channel Roles

| Channel | Role | Best For | Tone |
|---|---|---|---|
| X / Twitter | fast narrative + founder-build-in-public | product insight, short demo, technical hook | sharp, specific, compressed |
| LinkedIn | professional credibility | founder lesson, work productivity, AI adoption, hiring/investor signal | clear, grounded, slightly more explicit |
| Product Hunt | launch/release discovery | named release, changelog, demo GIF, maker comment | concise, benefit-first, community-aware |
| Reddit | community discussion | problem story, demo, request for feedback | conversational, no hype, disclose builder status |
| Dev.to | technical article | architecture, local-first, Swift, MCP, AI agent workflow | useful, explanatory, code/product detail |
| Hacker News | technical curiosity | strong technical insight, local-first/privacy/agent infra | plain, unsalesy, debate-ready |
| Indie Hackers | founder journey | building in public, traction, lessons, early users | candid, metrics-aware |
| YouTube / Shorts | visual proof | before/after demo, workflow recording | show result in first 3 seconds |
| Bilibili | Chinese product demo | longer Chinese walkthrough, founder narration | practical, demo-first |
| 即刻 | Chinese builder network | concise founder note, product insight | casual, human, not corporate |
| V2EX | Chinese technical community | Mac app, devtools, local-first details | respectful, technical, avoid marketing tone |
| 少数派 | productivity narrative | deep workflow story, local-first personal knowledge | polished, useful, scenario-rich |
| 微信公众号 / 朋友圈 | owned audience | release note, founder essay, private network | more context, less jargon |

## Drafting Rules

- Start from one feature, not the whole company.
- Explain the old pain before the new feature only when it helps the hook.
- Show a concrete artifact: screenshot, GIF, demo link, before/after query, or source-linked memory.
- Prefer "I built X because Y kept happening" over "we are excited to announce".
- Keep investor language out of user/community channels unless the audience is explicitly investor-facing.
- Avoid claims like "revolutionary", "game-changing", "the future of everything".

## Suggested CTAs

- Try it: `https://giiift.site/know-you/`
- Watch demo: `https://www.youtube.com/watch?v=UiaAVBtqBx0`
- Ask for feedback: "If you use AI coding agents every day, I would love to hear where they lose your context."
- Invite early users: "DM me if you want the TestFlight build."

## Visual Rules

- Show the actual KnowYou UI whenever possible.
- Use a short GIF for workflow changes.
- Use a 3-frame before/after image for features that change retrieval, memory, or agent output.
- Use generated imagery only as a secondary background or thumbnail, never as the main proof.

## Privacy Rules

Do not publish:

- phone number, birthday, home address, legal entity details unless necessary
- private chats, emails, diaries, logs, calendars, or memory excerpts without redaction
- investor application details or internal fundraising status
- screenshots that expose personal data, tokens, local file paths, or private project names

When using real context screenshots, redact names, emails, private paths, and message bodies unless the user explicitly approves that exact screenshot.
