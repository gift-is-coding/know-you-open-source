# Other Source 根级导航设计

## 摘要

KnowYou 的外部资料连接器不应只藏在设置面板里。用户需要在主界面左侧看到一个和 `My Diary` 平行的资料源导航模型：`My Diary` 负责自动生成日记，外部连接器则以独立根级项目出现，例如 `飞书文档`、`Obsidian Vault`、`Google Drive`。

同时，界面需要始终保留一个固定的 `Other Source` 入口。`Other Source` 不作为资料总览页，而是作为连接器管理页：用户从这里添加、删除、启用、停用和同步外部资料源。添加成功后，连接器自动出现在左侧根级导航中。

## 用户目标

- 用户能在主界面直接理解：`My Diary` 是自己的日记，其他根级项目是外部资料源。
- 用户能始终找到 `Other Source`，并通过它添加新的 Connector。
- 用户添加一个连接器后，能立即在侧边栏看到它成为一个和 `My Diary` 并列的入口。
- 用户点击连接器入口时，看到的是该连接器已同步到本地的内容，而不是设置表单。
- 用户知道同步语义：外部资料会复制进 KnowYou 本地存储，源文件不会被修改。

## 非目标

- 第一版不做 `Other Source` 全部资料总览页。
- 第一版不把多个连接器的内容混合成统一搜索页或统一知识库首页。
- 第一版不做外部资料编辑，也不把编辑写回飞书、Notion、Google Drive、Obsidian 或本地文件夹。
- 第一版不重做每日日记阅读器的信息架构。

## 信息架构

左侧导航根级项目固定包含：

- `My Diary`
- `Other Source`
- 用户添加的连接器实例，例如：
  - `飞书文档`
  - `Obsidian Vault`
  - `Google Drive`
  - `Project Docs`

`My Diary` 下面展示现有的日期分组和日记条目。

`Other Source` 始终存在，点击后进入连接器管理页。它旁边或行内需要有明显的 `+` 操作。`+` 和点击 `Other Source` 都可以打开同一个管理页，但 `+` 应直接聚焦到添加连接器流程。

连接器实例作为根级项目出现。每个连接器下面展示该连接器同步到本地的内容。内容层级应尊重连接器自己的结构：

- 本地文件夹和 Obsidian：按文件夹和 Markdown 文件结构展示。
- 飞书：按用户配置的文档、空间或文档树展示。
- Notion：按页面或数据库入口展示。
- Google Drive：按文件夹和文件展示。

## 交互流程

### 添加连接器

1. 用户点击左侧 `Other Source` 或其 `+` 按钮。
2. 主内容区显示连接器管理页。
3. 用户选择连接器类型，例如本地文件夹、Obsidian、飞书、Notion、Google Drive。
4. 用户完成必要配置。
5. KnowYou 保存连接器配置和凭据。
6. 新连接器实例立即出现在左侧根级导航中。
7. 系统提示用户可以立即同步或等待每日同步。

### 浏览连接器内容

1. 用户点击左侧根级连接器，例如 `飞书文档`。
2. 主内容区显示该连接器的已同步内容列表。
3. 用户选择一个文档。
4. 主内容区展示文档正文，正文使用 Markdown 或 Markdown-like 渲染。
5. 如果该连接器尚未同步、同步失败或本地内容为空，页面显示空状态和 `Sync Now` 操作。

### 管理连接器

1. 用户点击 `Other Source`。
2. 主内容区显示所有连接器实例。
3. 每个连接器 row 显示名称、类型、启用状态、最后同步时间、文档数量和最近错误。
4. 用户可以执行 `Sync Now`、`Enable/Disable`、`Delete`、`Configure`。
5. 页面保留每日导入开关和导入时间。

## 页面职责

### My Diary

`My Diary` 保持现有日记阅读职责。它不展示外部资料连接器，也不承载添加连接器入口。

### Other Source 管理页

`Other Source` 是连接器控制台，负责：

- 添加新的连接器。
- 展示所有连接器状态。
- 管理连接器启用状态。
- 触发手动同步。
- 设置每日同步。
- 删除连接器。
- 解释本地存储和循环防护语义。

文案必须明确：

- 外部资料会复制到 KnowYou 本地存储。
- 源文件不会被 KnowYou 修改。
- `Daily Memory Export` 和 `Knowledge Imports` 是两条独立通道。
- 如果同时配置 Obsidian 导出和 Obsidian 导入，KnowYou 会跳过自己导出的日记目录或带有导出标记的文件，避免循环。

### 连接器内容页

连接器内容页负责浏览和阅读，不负责复杂配置。它应包含：

- 连接器标题。
- 最近同步状态。
- `Sync Now` 操作。
- 本地内容树或列表。
- 文档阅读区。
- 空状态和错误状态。

第一版可以用单列列表加 Markdown 阅读区实现。后续再扩展为三栏资料浏览器或搜索页。

## 数据要求

现有 `KnowledgeImportConfig.connectorInstances` 可以作为左侧根级连接器列表的来源。每个连接器实例至少需要提供：

- `id`
- `connectorID`
- `displayName`
- `sourcePath`、`accountID` 或 `workspaceID`
- `isEnabled`

连接器内容页需要能读取本地导入缓存和 SQLite 索引。第一版可以先使用本地 `KnowledgeSources` 存储和现有 metadata 生成内容列表；如果索引还不能完整支撑树形展示，可以先按连接器实例列出已导入文档。

导航选择状态需要从单一 `selectedDate` 升级为更通用的主选择模型。建议引入类似：

- `diary(dayKey: String)`
- `otherSourceManager`
- `connector(instanceID: String)`
- `knowledgeDocument(documentID: String)`

这样可以避免用日期字符串承载非日记页面。

## 错误与空状态

连接器内容页需要覆盖：

- 未同步：显示 `No documents yet` 和 `Sync Now`。
- 同步中：显示同步进度或状态。
- 同步失败：显示最近错误和重试按钮。
- 连接器被禁用：显示禁用状态和启用入口。
- 凭据缺失或过期：提示回到 `Other Source` 管理页重新配置。

单个连接器失败不影响其他连接器在侧边栏显示。

## 隐私与安全

`Other Source` 管理页必须明确外部资料导入是用户主动选择的行为。导入内容保持本地存储，不因为导入动作自动发送给 LLM provider。

API token 和 bearer token 必须继续放在 Keychain。侧边栏和内容页不得显示 token。

## 测试策略

需要新增或更新测试覆盖：

- 侧边栏 presentation 会固定包含 `My Diary` 和 `Other Source`。
- 配置一个连接器实例后，侧边栏会把该实例显示为根级项目。
- 点击 `Other Source` 会进入管理页，而不是资料总览页。
- 点击连接器会进入内容页，而不是打开配置表单。
- `Other Source` 的 `+` 操作会打开添加连接器流程。
- 删除连接器后，侧边栏对应根级项目消失。
- 连接器禁用后仍可出现在侧边栏，但内容页显示禁用状态。
- 没有同步内容时，连接器内容页显示空状态和 `Sync Now`。

## 验收标准

- 用户打开主窗口后，无需进入齿轮菜单，也能看到 `Other Source`。
- 用户能从 `Other Source` 添加连接器。
- 添加连接器后，它以根级项目出现在侧边栏，和 `My Diary` 并列。
- 点击根级连接器可以浏览已同步内容。
- 连接器设置和内容浏览职责清晰分离。
- UI 文案解释本地存储、源文件不修改、Obsidian 循环防护。
